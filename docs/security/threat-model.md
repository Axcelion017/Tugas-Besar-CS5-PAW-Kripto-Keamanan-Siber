# Model Ancaman STRIDE — Resilio-Health

Dokumen ini menganalisis model ancaman keamanan siber pada sistem informasi rumah sakit Resilio-Health menggunakan metodologi **STRIDE** (*Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service, Elevation of Privilege*) yang diselaraskan dengan kebutuhan dunia nyata dan arsitektur *Offline-First Zero-Trust*.

---

## 1. Analisis Ancaman STRIDE Terperinci

| ID Ancaman | Kategori STRIDE | Elemen DFD Terdampak | Aset Terdampak | Deskripsi Skenario Ancaman Dunia Nyata | Dampak Potensial | Kontrol Mitigasi pada Resilio-Health |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **THR-01** | **Spoofing** | EXT-01, PRC-01 | AST-03, AST-06 | **Pendaftaran Akun Pasien Fiktif**: Penyerang membuat akun dengan NIK sembarang untuk memperoleh akses ke data faskes. | Duplikasi identitas, klaim asuransi fiktif, polusi basis data RME. | **Verifikasi KYC (KTP)**: Status akun terkunci `PENDING` hingga nomor NIK divalidasi cocok dengan foto fisik KTP oleh Admin Regulator. |
| **THR-02** | **Tampering** | DS-01, TB-2 | AST-01, AST-04 | **Manipulasi Rekam Medis di Penyimpanan Lokal / Transit**: Malware atau pengguna mengubah dosis obat atau diagnosis pada berkas offline. | Malpraktik dosis obat fatal, kesalahan tindakan medis darurat. | **Integritas HMAC-SHA256 (Fail-Closed)**: Setiap rekam medis diberi tag HMAC; jika 1 bit berubah, server menolak sinkronisasi dan klien menolak dekripsi. |
| **THR-03** | **Repudiation** | EXT-01, PRC-03 | AST-01, AST-04 | **Penyangkalan Tindakan Medis (Non-Repudiation Failure)**: Dokter menyangkal pernah memberikan resep atau mendiagnosis penyakit tertentu kepada pasien. | Sengketa hukum malpraktik tanpa alat bukti digital yang sah (UU ITE & Permenkes 24/2022). | **Atribusi STR/SIP & Timestamp Kriptografis**: Rekam medis mengikat nomor STR dan SIP dokter yang bertugas secara tidak dapat disangkal ke dalam ciphertext. |
| **THR-04** | **Information Disclosure** | TB-2, DS-01 | AST-01 | **Kebocoran Rekam Medis oleh Admin / Cloud Provider**: Database bocor atau staf IT internal membaca diagnosis sensitif pasien. | Pelanggaran berat privasi medis (UU PDP No. 27/2022), sanksi pidana dan denda administratif. | **Zero-Knowledge Storage (AES-256-GCM)**: Seluruh isi klinis SOAP dienkripsi di peramban dengan kunci privat pasien; Admin dan Database hanya melihat ciphertext opaque. |
| **THR-05** | **Denial of Service** | PRC-01, PRC-05 | AST-05, AST-07 | **Downtime Chaos & Ransomware Lockdown**: Server pusat lumpuh atau koneksi internet faskes putus sehingga dokter tidak dapat mengakses data pasien. | Pelayanan rumah sakit terhenti total, penanganan pasien gawat darurat tertunda berjam-jam. | **Ketahanan Offline-First PWA (IndexedDB Engine)**: Service Worker dan antrean IndexedDB memungkinkan dokter tetap membaca cache antrean dan menginput RME saat offline. |
| **THR-06** | **Elevation of Privilege** | PRC-02, DS-03 | AST-01, AST-03 | **Serangan BOLA / IDOR (Broken Object Level Authorization)**: Dokter menebak parameter `id_pasien` di URL API untuk mengunduh rekam medis pasien lain tanpa izin. | Kebocoran data rekam medis massal (seperti pada 96% kasus kebocoran web kesehatan). | **Zero-Trust BOLA / IDOR Gate**: Gateway memverifikasi keberadaan tiket izin aktif (`access_grants`) sebelum mengembalikan data; akses ilegal diblokir 403 Forbidden. |
| **THR-07** | **Tampering** | PRC-03, DS-01 | AST-02 | **Serangan Penggunaan Ulang IV (IV Reuse Attack)**: Penggunaan kembali Initialization Vector (IV) pada AES-GCM dengan kunci yang sama. | Melemahkan jaminan otentisitas Galois/Counter Mode dan memungkinkan pembobolan kunci simetris. | **CSPRNG 96-bit Nonce**: Pembangkitan IV 12 bytes unik per sesi enkripsi menggunakan `window.crypto.getRandomValues()`. |
| **THR-08** | **Spoofing** | EXT-01, PRC-01 | AST-06 | **Penyusupan Dokter Gadungan (Rogue Doctor)**: Pengguna mendaftar sebagai tenaga medis tanpa izin praktik resmi untuk menulis rekam medis. | Masuknya catatan medis ilegal dan malpraktik massal di faskes. | **Verifikasi KYD (STR & SIP)**: Akun nakes tidak dapat memanggil API RME sebelum dokumen STR dan SIP divalidasi keabsahannya oleh Admin Regulator Kemenkes. |
| **THR-09** | **Information Disclosure** | AST-02, PRC-04 | AST-02 | **Penyimpanan Kunci Kriptografi Tidak Aman**: Kunci enkripsi tersimpan dalam format hardcoded di repositori atau terekspos ke localStorage publik. | Kompromi total terhadap seluruh data terenkripsi pasien. | **Runtime Memory Isolation**: Kunci simetris didelegasikan saat sesi aktif dan dibersihkan dari peramban saat pengguna keluar sistem (*Logout Modal*). |
| **THR-10** | **Repudiation** | PRC-02, AST-04 | AST-04 | **Penyangkalan Pencabutan Izin (Revoke Dispute)**: Faskes mengklaim masih memiliki izin membuka rekam medis pasien yang telah berpindah rumah sakit. | Sengketa hak kepemilikan data pribadi antara pasien dan faskes lama. | **1-Click Digital Revoke & Immutable Audit Trail**: Perubahan status grant menjadi `REVOKED` dicatat seketika dengan timestamp lokal dan alamat IP pengakses. |
