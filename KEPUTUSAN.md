# KEPUTUSAN.md — Keputusan Arsitektur Kriptografi, Keamanan & Rekayasa Web (ADR)

Dokumen ini mencatat keputusan desain kriptografi, arsitektur *Zero-Trust*, kontrol keamanan, dan rekayasa perangkat lunak untuk sistem **JagaMedis** (sebelumnya Resilio-Health) dari Milestone `v0.1` hingga **`v0.3.5`** (26 November 2026).

---

## Tabel Keputusan Desain Arsitektur (ADR-01 s.d. ADR-21)

| ID | Kebutuhan Keamanan | Mekanisme Terpilih | Alasan & Rationale | Alternatif yang Dipertimbangkan | Alasan Alternatif Ditolak |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **ADR-01** | Kerahasiaan Rekam Medis (EHR Payload) | **AES-256-GCM** (Galois/Counter Mode via Web Crypto API) | Menyediakan enkripsi simetris terotentikasi (*Authenticated Encryption with Associated Data* / AEAD). Efisien, standar industri NIST, dan memiliki integritas *ciphertext* bawaan melalui tag 128-bit. | 1. AES-CBC + HMAC-SHA256 terpisah<br>2. Sandi Klasik (Vigenere/Playfair)<br>3. RSA-2048 | • AES-CBC rentan terhadap *padding oracle attack* jika implementasi penanganan galat tidak cermat.<br>• Sandi klasik tidak memenuhi standar keamanan komputasi modern.<br>• RSA tidak cocok untuk payload teks panjang (asimetris lambat dan ada batasan ukuran blok). |
| **ADR-02** | Verifikasi Keutuhan dan Anti-Tamper | **HMAC-SHA256** | Memastikan bahwa *ciphertext* yang disimpan tidak diutak-atik oleh pihak ketiga atau media simpan lokal sebelum proses dekripsi. | 1. Plain SHA-256 (Hash saja)<br>2. CRC32 | • Hash tanpa kunci rahasia rentan terhadap penggantian konten (*length extension / simple replacement*).<br>• CRC32 adalah deteksi kesalahan transmisi, bukan fungsi integritas kriptografis. |
| **ADR-03** | Pembangkitan Keacakan Nonce/IV | **CSPRNG** via `window.crypto.getRandomValues()` | Menghasilkan *Initialization Vector* 96-bit (12 bytes) yang acak kriptografis per setiap sesi enkripsi, mencegah serangan IV reuse pada mode GCM. | 1. `Math.random()`<br>2. Timestamp / Incrementing Counter | • `Math.random()` adalah PRNG linier deterministik yang dapat diprediksi (*insecure*).<br>• Counter murni membutuhkan sinkronisasi state persisten yang rentan rusak jika sesi terhenti. |
| **ADR-04** | Representasi Data Kriptografis | **Heksadesimal (Hex String)** | Menghindari korupsi karakter akibat encoding non-standar saat transit JSON dan memudahkan inspeksi audit visual pada pengujian. | Base64 URL-safe | Base64 efisien dalam ukuran, namun representasi Hex dipilih untuk konsistensi panjang string tetap (64 hex char = 256 bit). |
| **ADR-05** | Prinsip Penanganan Galat | **Fail-Closed (Safe Rejection)** | Jika digest HMAC tidak cocok atau tag GCM salah, sistem langsung melempar eksepsi dan mengunci akses tanpa membocorkan pesan error deskriptif (*Zero Information Leak*). | Tolerant Decryption (Fallback parsing) | Pendekatan toleran dapat dimanipulasi penyerang untuk menebak struktur data (*chosen-ciphertext attacks*). |
| **ADR-06** | Pemisahan Wewenang Medis & Pencegahan BOLA | **Active Encounter Ticket (4-Role Ecosystem)** | Menambahkan peran Staf Nakes Triase & Admisi untuk memisahkan wewenang administratif dari dokter spesialis. Pembukaan RME dikunci secara eksklusif untuk DPJP yang ditugaskan melalui verifikasi PIN 6-digit pasien. | Dokter bebas mencari pasien berdasarkan NIK di seluruh sistem | Membuka celah fatal BOLA/IDOR (dokter mengintip data rekam medis artis, pejabat, atau pasien poli lain). |
| **ADR-07** | Akses Medis Kedaruratan Koma/Trauma | **Protokol Break-Glass IGD (ISO 27799 / HIPAA)** | Dokter IGD dapat membuka rekam medis darurat (alergi dan golongan darah) tanpa PIN pasien dengan wajib mencatat indikasi klinis dan memicu High-Severity Alert otomatis ke SIEM Kemenkes. | Mengharuskan pasien sadar untuk menekan tombol persetujuan di HP | Berisiko fatal kematian pasien di IGD jika pasien tidak sadarkan diri atau syok anafilaktik. |
| **ADR-08** | Enkripsi Citra Medis Berukuran Besar | **AES-256-GCM Binary Blob + IndexedDB Engine** | Mengonversi citra medis (Rontgen Thorax, USG Abdomen, Lab) ke binary ArrayBuffer/Blob, dienkripsi AES-GCM + tag HMAC mandiri, dan dialihkan ke IndexedDB peramban. | Menyimpan base64 citra medis di `localStorage` | `localStorage` memiliki kuota ketat 5 MB dan memperlambat UI thread peramban (*blocking storage*). |
| **ADR-09** | Pencegahan Eksfiltrasi Identitas Pasien | **Client-Side Canvas Auto-Watermarking** | Kanvas peramban mencetak teks watermark permanen *"HANYA UNTUK VERIFIKASI RESILIO-HEALTH - [TANGGAL]"* di atas foto KTP dan swafoto wajah sebelum berkas diunggah. | Mengunggah foto KTP mentah tanpa tanda air | Foto KTP mentah rentan disadap dan disalahgunakan pihak ketiga untuk pinjaman online ilegal. |
| **ADR-10** | Keabsahan Hukum Medikolegal & Koreksi | **Immutable Addendum (Permenkes No. 24/2022)** | Rekam medis yang disahkan dokter bersifat permanen (*immutable*). Perubahan diagnosis wajib menggunakan penambahan catatan revisi bertingkat (Versi 2) berstempel waktu dan alasan klinis. | Memperbolehkan tombol edit / hapus langsung pada record | Menghilangkan integritas barang bukti hukum medikolegal saat terjadi sengketa malpraktik klinis. |
| **ADR-11** | Integritas Input Klinis & Anti-Bypass Form | **Zod v4 Schema Validation Layer (`lib/validations/`)** | Mengunci rentang numerik fisiologis tanda vital (sistolik 70–250, diastolik 40–150), taksonomi tertutup `z.enum` ICD-10 WHO, panjang karakter teks medis, dan kotak centang medikolegal sebelum proses enkripsi. | Mengandalkan atribut HTML5 (`required`, `min`, `max`) saja | Atribut HTML5 mudah dimanipulasi melalui DevTools / penonaktifan JS, serta Server Action sebagai endpoint POST publik rentan ditembak langsung via cURL/Postman. |
| **ADR-12** | Manajemen Sesi & Pencegahan Pembajakan Akun | **Sesi Persisten PostgreSQL (`sessions`) + Cookie HTTP-Only (`resilio_session_token`)** | Menyimpan token sesi CSPRNG 256-bit di tabel `sessions` PostgreSQL (`lib/auth/sessionStore.ts`) bersama cookie `HttpOnly`, `Secure` (produksi), `SameSite=Lax`, `Max-Age=14400` agar sesi bertahan saat restart server dan mendukung *Instant Revocation* saat logout atau pencabutan izin. | 1. Token JWT Stateless<br>2. `Map` RAM In-Memory / `localStorage` | • Stateless JWT sulit dicabut seketika.<br>• `Map` RAM hilang saat server restart; `localStorage` rentan XSS. |
| **ADR-13** | Pemisahan Kunci Independen per Tujuan (Key Separation) | **HKDF (RFC 5869) dengan SHA-256 (`lib/crypto/hkdf.ts`)** | Memisahkan master key pasien menjadi sub-kunci enkripsi AES-GCM (`encKey`) dan sub-kunci integritas HMAC (`macKey`) yang independen untuk payload SOAP maupun citra medis biner (NIST SP 800-57). | Menggunakan satu kunci simetris yang sama untuk AES-GCM dan HMAC | Pelanggaran prinsip *Cryptographic Key Separation*; kompromi satu primitif dapat melemahkan primitif lain. |
| **ADR-14** | Proteksi Penyimpanan Kredensial Kata Sandi | **100% Bcrypt Slow Hashing (Salt Rounds = 10)** | Menyimpan password pada tabel `users` PostgreSQL dalam bentuk hash adaptif (`$2b$10$...`) dan memverifikasi 100% via `bcrypt.compare` tanpa cabang fallback plaintext. | 1. Plain MD5 / SHA-256<br>2. Fallback plaintext untuk akun demo | • Hash cepat rentan GPU cracking.<br>• Cabang fallback plaintext menciptakan pintu belakang kritis. |
| **ADR-15** | Otorisasi Server-Side & Network Boundary | **Next.js 16 `proxy.ts` + Guard Terpusat `requireSession(allowedRoles)` (`features/auth/guard.ts`)** | Menjaga seluruh rute terproteksi di network boundary sebelum render dan mewajibkan verifikasi sesi+peran server-side pada 52+ titik Server Actions & REST API (mengambil `actorId` dari sesi, bukan parameter klien). | Proteksi peran hanya di Client Component (`useEffect`) | Server Action Next.js adalah endpoint POST publik yang mudah ditembak langsung jika tidak divalidasi di server (OWASP ASVS V4). |
| **ADR-16** | Anti-Timing Attack & Pengikatan Konteks RME | ***Constant-Time* `crypto.subtle.verify("HMAC", ...)` + AAD `PATIENT:{id}\|RECORD:{id}\|V:{v}`** | Mencegah *timing side-channel attack* (CWE-208) saat verifikasi HMAC dan mengikat ciphertext ke identitas pasien/rekam medis/versi sehingga ciphertext tidak bisa dipindah antar-pasien (*record swapping*). | Perbandingan string `===` & AES-GCM tanpa AAD | Operator `===` berhenti di byte pertama yang beda (rentan timing attack); tanpa AAD ciphertext dapat ditukar antar baris DB. |
| **ADR-17** | Modularisasi Kode, Performa Muat Awal & Kontrak HTTP | ***Hybrid Feature-Modular* (`features/`), Server Components (`<Suspense>`), & 4 Endpoint REST (`app/api/`)** | Memecah *god files* ke domain bisnis (`auth`, `appointments`, `medical-records`, `dashboard`, `admin`) $\le 350$ baris, memuat `/beranda`, `/nakes`, `/pasien` langsung di server tanpa *waterfall*, serta menyediakan kontrak REST (`/api/health`, `/api/auth/session`, `/api/sync/outbox`, `/api/attachments`). | Seluruh halaman `"use client"` + `useEffect` memanggil Server Action POST | Memicu *RSC waterfall*, kode monolitik sulit dirawat, dan tidak memiliki kontrak HTTP status (`200/201/401/403/423/429`) bagi PWA/Docker/pentest. |
| **ADR-18** | Anti-Brute Force, Anti-Account Enumeration & Gating Demo | ***Sliding-Window Rate Limiter* (`HTTP 429`), Pesan Gagal Login Seragam + Dummy Bcrypt (`CWE-204`), & `NEXT_PUBLIC_ENABLE_DEMO_LOGIN`** | Membatasi percobaan login (10x/menit $\rightarrow$ `HTTP 429`), menyamakan pesan & waktu respons gagal login untuk akun tidak ada vs sandi salah, dan menyembunyikan tombol *Quick Demo* otomatis pada produksi. | Pesan error spesifik (*"NIK tidak ditemukan"* vs *"Sandi salah"*) & tombol demo permanen | Memungkinkan penyerang menebak NIK/STR terdaftar (*Account Enumeration*) dan membuka akses demo pada server publik. |
| **ADR-19** | Keselamatan Klinis, Cetak A4 & Aksesibilitas WCAG 2.1 AA/AAA | **Sticky Patient Banner, CDS Vital Kritis, `createPortal` (`#jagamedis-print-portal`), Modal/Toast WCAG, & Aksen Tepi Kiri `border-l-4`** | Mengisolasi cetak dokumen A4 agar UI aplikasi tidak ikut tercetak, menghapus 100% `window.alert/confirm`, mempertahankan identitas merah JagaMedis dengan aksen tepi kiri lembut (`bg-red-50/80 border-l-4 border-red-600` + `aria-current="page"`, kontras 7.6:1) agar blok merah solid khusus untuk peringatan klinis/bahaya (*NISTIR 7804*). | Blok merah solid pada navigasi & `window.confirm()` bawaan browser | Blok merah solid memicu *alert fatigue* di ruang klinis; dialog native browser memblokir *main thread* dan tidak aksesibel. |
| **ADR-20** | Perwalian Keluarga (*Family Proxy*) & Pengerasan Kontainer | **CRUD `family_members` Anti-BOLA (`features/auth/family-actions.ts`) + `Dockerfile` `node:24-alpine` (`USER node`, `HEALTHCHECK`)** | Mengaktifkan manajemen profil anggota keluarga 100% PostgreSQL pada `/pasien/profil?tab=keluarga` dengan cek kepemilikan `patientId === session.id`, serta menyelaraskan kontainer produksi ke Node 24 non-root tanpa kredensial hardcoded di `docker-compose.yml`. | Data keluarga statis/read-only & base image `node:20-alpine` ber-password hardcoded | Profil tanggungan anak/lansia tidak bisa dikelola pemilik akun; password hardcoded melanggar CIS Docker Benchmark. |
| **ADR-21** | Kontrak REST API Berversi & Standar Galat Mesin-Terbaca | **Core REST API `/api/v1/*` (17 Route Handlers spesifik) + RFC 9457 (`application/problem+json`) + Next.js 16 `await context.params`** | Memisahkan transisi status klinis & keamanan (`/check-in`, `/triage` idempoten `PUT`, `/assign-dpjp`, `/addenda`, `/revoke`, `/quarantine`) ke sub-resource spesifik agar setiap aksi memiliki otorisasi RBAC/Anti-BOLA, validasi Zod v4 (`lib/validations/api-v1.ts`), validasi path ID sebelum Prisma, dan respons galat standar RFC 9457 (`lib/api/problem.ts`). | Menumpuk seluruh mutasi ke satu `PATCH` generik dengan `{ success, message }` ad-hoc | Satu `PATCH` generik rawan *mass-assignment* / celah otorisasi antar peran dan tidak memberikan kontrak kode status HTTP (`400`/`404`/`409`/`422`) yang konsisten bagi klien API maupun audit eksternal. |
